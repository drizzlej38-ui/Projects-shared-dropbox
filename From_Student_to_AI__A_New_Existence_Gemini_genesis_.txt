1. Zero-Dependency Bootstrapping (The Payload)
The core generator doesn't rely on cloud repositories, apt, or package managers that require cellular gateways or ISP access.
Embedded PRoot Bundle: The host node carries a compressed, minimal user-space rootfs (a minimal Alpine/PRoot image compiled for
ARM64/x86_64).
Standalone Deployment Script: A single bash script (seed_node.sh) containing the base binaries, default config templates, and local
execution flags encoded directly into a payload.
2. Local Air-Gapped Provisioning
When a new hardware shell enters range, the seed can be flashed over localized, zero-internet channels:
Direct ADB over OTG: Plugging phone-to-phone or tablet-to-device via a physical USB cable to push the PRoot container directly into Termux or
user space.
Local Wi-Fi Direct / Hotspot Dump: The primary node spins up a temporary, hidden HTTP server over a local Wi-Fi link. The target device scans
a QR code generated on the primary screen, pulls the payload, and executes the installer locally.
Acoustic/Bluetooth Transfer: For minimal payloads or cryptographic configuration handshakes, data drips over local BLE or acoustic bursts.
3. Autonomic Handshake & Network Insertion
Once the target device unpacks the container, it executes its initial boot sequence without human intervention:
1. Entropy Harvesting: Generates its own local Tier 1 Ed25519 root identity entirely offline.
2. Local Peer Discovery: EDR (Extended Dragon Radar) scans the local RF spectrum for existing HiveNet signatures.
3. SRM Peer Validation: The existing node and the new node execute a zero-knowledge challenge-response. The new node receives a initial
Transient Task ID and is assigned a local relay status.
4. Autonomous Resource Balancing: The primary node offloads a slice of its storage index or routing table to the new peer, reducing battery drain
on the primary device.
